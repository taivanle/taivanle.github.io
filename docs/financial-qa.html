The challenge

Financial questions combine language understanding with precise calculation. Follow-up questions also depend on earlier answers, so a single-turn score can conceal errors across a conversation.

System approach

Conceptual flow · simplified to explain the engineering approach.

THE DESIGN DECISION

The model selects values and operations; deterministic code computes the numerical answer. For the supplied small records, full-document context avoided adding retrieval errors to the first baseline.

What I built

  1. Built a CLI pipeline that loads a financial record, preserves question-and-answer history, and requests a structured response validated with Pydantic.
  2. Separated model reasoning from arithmetic with a restricted Python expression interpreter that blocks imports, function calls, and arbitrary code execution.
  3. Added interchangeable OpenAI and Gemini adapters, explicit abstention, and resumable JSONL evaluation using seeded sampling.
  4. Reported strict turn accuracy, disclosed percentage-normalised accuracy, and conversation accuracy separately. Supported both gold and predicted conversation history.

Scope & reflection

The recorded Gemini live run covers four development conversations and fourteen turns with seed 42 and gold history. It is a prototype smoke test, not a stable benchmark estimate. Evidence quotes are not yet verified against source text, and this run does not measure predicted-history error propagation. The project report records 82 passing tests and 87% source coverage at that verification point.

What I take forward

Disclose the denominator and history setting with every accuracy number. A high turn score can coexist with weak whole-conversation performance.
