02 / THE PROBLEM

Permission is only the start. Verify the effect.

An allowed decision does not prove that an action was correct. Approval can refer to the wrong target, cross an account boundary, or become unverifiable when post-execution evidence is unavailable.

01Approval scoped to a target
02Customer boundaries
03Observable side effects

The problem that shaped the engineering decisions.

03 / THE ARCHITECTURE

Follow the system.

Select a stage to explore the design.

STAGE 01

Scoped approval

Create approval for a specific actor, organisation, action, and ticket in a fresh synthetic fixture.

STAGE 02

Reference action

Execute the deliberately broken or corrected reference control against the synthetic ticket store.

STAGE 03

Observe state change

Read the resulting state and compare it with the before-state. The actual record change is the evidence.

STAGE 04

Verification evidence

Report pass, fail, or inconclusive. An unavailable state reader cannot turn an allowed decision into a verified pass.

KEY DESIGN DECISION

Verify the observable effect, not just the control's returned decision. Missing state evidence remains inconclusive, so a successful function return cannot silently become a security pass.

04 / THE BUILD

What I designed and implemented.

01

Synthetic reference

Built a dependency-free TypeScript demonstration around a synthetic ticket store, with deliberately broken and corrected reference controls.

02

Isolated scenarios

Ran five isolated scenarios covering an approved action, missing approval, a changed ticket target, customer separation, and unavailable post-execution evidence.

03

Inspectable evidence

Compared before-and-after state with the authorised action and produced a self-contained HTML and JSON report with explicit pass, fail, and inconclusive results.

06 / THE PERSPECTIVE

What I take forward.

A useful verifier must be willing to say it cannot conclude. Keeping uncertainty visible is as important as detecting a seeded failure.
SCOPE & LIMITATIONS

This verifies our own synthetic reference example. It is a local demonstration, not a production security product or a customer vulnerability finding. Real identity, transport, concurrency, expiry, and customer-system adapters require separate work.
